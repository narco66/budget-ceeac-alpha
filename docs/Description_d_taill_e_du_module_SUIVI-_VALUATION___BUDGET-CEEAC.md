# DESCRIPTION DÉTAILLÉE DU MODULE SUIVI-ÉVALUATION  
## Application BUDGET-CEEAC

## 1. OBJET DU MODULE

Le module **SUIVI-ÉVALUATION** de BUDGET-CEEAC est le dispositif central permettant de mesurer, analyser, documenter et piloter la mise en œuvre des programmes, activités et tâches inscrits au Budget et au PAP de la Commission de la CEEAC.

Il ne doit pas être conçu comme un simple tableau de bord de consommation budgétaire.

Il doit permettre de rapprocher en permanence :

**la planification**,  
**l’exécution physique**,  
**l’exécution financière**,  
**les indicateurs de performance**,  
**les résultats obtenus**,  
**les écarts**,  
**les risques**,  
**les mesures correctives**,  
**les évaluations**,  
et **le reporting institutionnel**.

Le module doit fournir une vision complète permettant de répondre à une question fondamentale :

> Les ressources mobilisées par la Commission de la CEEAC produisent-elles effectivement les résultats programmés, dans les délais, aux coûts prévus et avec le niveau de performance attendu ?

# 3. OBJECTIFS DU MODULE

Le module doit notamment permettre de :

1. suivre l’exécution physique des activités et tâches ;
2. suivre l’exécution financière ;
3. suivre les indicateurs ;
4. comparer prévisions et réalisations ;
5. suivre les échéances ;
6. détecter les retards ;
7. détecter les sous-performances ;
8. détecter les dépassements ;
9. mesurer les écarts physiques et financiers ;
10. documenter les causes des écarts ;
11. définir des actions correctives ;
12. suivre les risques ;
13. suivre les recommandations ;
14. produire des évaluations périodiques ;
15. calculer les taux de performance ;
16. consolider les résultats par niveau organisationnel ;
17. consolider les résultats par programme ;
18. consolider les résultats par activité ;
19. produire des rapports périodiques ;
20. alimenter les tableaux de bord décisionnels ;
21. conserver les preuves de réalisation ;
22. assurer la traçabilité des évaluations ;
23. soutenir les décisions de réallocation et d’arbitrage ;
24. mesurer progressivement l’atteinte des objectifs du PAP.

# 11. RÉALISATION PHYSIQUE

Le module doit permettre de renseigner la réalisation effective d’une activité ou tâche.

Pour chaque tâche :

- résultat attendu ;
- unité de mesure ;
- quantité prévue ;
- quantité réalisée ;
- pourcentage d’avancement ;
- date ;
- responsable ;
- commentaire ;
- preuve.

Exemple :

**Tâche : Former 100 agents**

Prévu : 100

Réalisé : 75

Taux physique :

**75 %**

---

# 12. AVANCEMENT PHYSIQUE

Le système doit pouvoir calculer automatiquement :

**Taux d’avancement physique = Réalisation / Cible × 100**

Lorsque plusieurs tâches composent une activité, le calcul doit pouvoir utiliser :

- moyenne simple ;
- moyenne pondérée ;
- pondération configurée.

---

# 13. PONDÉRATION DES TÂCHES

Une activité comportant plusieurs tâches ne doit pas nécessairement considérer chaque tâche comme équivalente.

Exemple :

| Tâche | Poids |
|---|---:|
| Étude | 20 % |
| Acquisition | 30 % |
| Déploiement | 40 % |
| Formation | 10 % |

Le taux global doit respecter les pondérations.

# 23. COMPARAISON PHYSIQUE / FINANCIÈRE

C’est une fonction centrale du module.

Exemple :

**Exécution physique : 35 %**

**Exécution financière : 75 %**

Écart :

**40 points**

Le système doit afficher une alerte :

**Écart significatif entre exécution physique et financière**

---

# 24. INTERPRÉTATION DES ÉCARTS

Exemples :

### Finance > Physique

Possible :

- avance importante ;
- dépenses engagées avant réalisation ;
- surcoût ;
- retard technique.

### Physique > Finance

Possible :

- factures non encore traitées ;
- prestations réalisées mais non payées ;
- contribution non monétaire ;
- décalage de comptabilisation.

Le système doit permettre d’enregistrer l’explication.

# 39. SCORE DE PERFORMANCE

Le système doit pouvoir calculer un score composite.

Exemple :

**Performance physique : 40 %**

**Performance financière : 30 %**

**Respect des délais : 15 %**

**Qualité : 15 %**

Le poids de chaque composante doit être paramétrable.

---

# 40. EXEMPLE DE CALCUL

Exemple :

- physique : 80 × 40 % = 32 ;
- financier : 70 × 30 % = 21 ;
- délai : 60 × 15 % = 9 ;
- qualité : 90 × 15 % = 13,5.

Score total :

**75,5 / 100**

---

# 41. CLASSEMENT DE PERFORMANCE

Exemple paramétrable :

90–100 :

**Excellent**

75–89 :

**Satisfaisant**

60–74 :

**À améliorer**

40–59 :

**Insuffisant**

< 40 :

**Critique**

# 100. VISION CIBLE

Le module SUIVI-ÉVALUATION de BUDGET-CEEAC doit devenir un véritable **système de pilotage de la performance institutionnelle et budgétaire**.

Il doit être capable de démontrer :

- ce qui avait été prévu ;
- ce qui a réellement été réalisé ;
- combien cela a coûté ;
- ce qui a été engagé, liquidé, ordonnancé et payé ;
- quels résultats ont été obtenus ;
- quels indicateurs ont été atteints ;
- quels écarts persistent ;
- quelles difficultés ont été rencontrées ;
- quelles actions correctives ont été décidées ;
- quelles recommandations restent ouvertes ;
- quelles décisions doivent être prises.

Le module doit ainsi constituer un dispositif intégré de :

**planification opérationnelle**,  
**suivi physique**,  
**suivi financier**,  
**mesure des indicateurs**,  
**analyse des écarts**,  
**gestion des risques**,  
**évaluation**,  
**suivi des recommandations**,  
**reporting**,  
**aide à la décision**,  
**traçabilité**,  
et **pilotage de la performance**.

Le principe directeur doit rester :

**Planifier → Exécuter → Mesurer → Comparer → Analyser → Corriger → Évaluer → Rapporter → Décider → Améliorer.**
