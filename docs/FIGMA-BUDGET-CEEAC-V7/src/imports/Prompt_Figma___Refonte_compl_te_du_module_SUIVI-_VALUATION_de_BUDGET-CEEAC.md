# PROMPT FIGMA — REFONTE COMPLÈTE DU MODULE SUIVI-ÉVALUATION DE BUDGET-CEEAC

## 1. CONTEXTE GÉNÉRAL

Tu travailles sur la maquette Figma existante de **BUDGET-CEEAC**, application intégrée de planification, budgétisation, exécution budgétaire, suivi-évaluation, gestion documentaire, reporting et pilotage de la performance de la Commission de la CEEAC.

Je joins à ce prompt le fichier contenant la :

# « DESCRIPTION DÉTAILLÉE DU MODULE SUIVI-ÉVALUATION DE BUDGET-CEEAC »

Ce document constitue désormais la **référence fonctionnelle principale pour la refonte du module SUIVI-ÉVALUATION**.

Ta mission consiste à réaliser une **refonte complète, profonde, cohérente et professionnelle du module Suivi-Évaluation dans la maquette Figma existante**.

Il ne s’agit pas simplement d’améliorer graphiquement quelques tableaux de bord.

Tu dois réexaminer entièrement :

- l’architecture fonctionnelle ;
- les parcours utilisateurs ;
- le suivi du PAP ;
- le suivi Hors PAP pertinent ;
- le suivi physique ;
- le suivi financier ;
- les indicateurs ;
- les valeurs de référence ;
- les cibles ;
- les réalisations ;
- les écarts ;
- le Gantt ;
- les tâches ;
- les jalons ;
- les dépendances ;
- les risques ;
- les problèmes ;
- les actions correctives ;
- les évaluations ;
- les recommandations ;
- les plans d’action ;
- les rapports ;
- les tableaux de bord ;
- les notifications ;
- les preuves de réalisation ;
- la GED ;
- les workflows ;
- les validations ;
- les historiques ;
- l’audit ;
- les vues décisionnelles.

La nouvelle maquette doit faire du Suivi-Évaluation un véritable **système de pilotage de la performance physique, financière et institutionnelle**.

---

# 2. OBJECTIF FONDAMENTAL

Le module doit permettre de répondre clairement à la question :

> Les ressources budgétaires mobilisées produisent-elles réellement les résultats programmés, dans les délais prévus, avec les niveaux de performance attendus ?

Le module doit donc rapprocher en permanence :

**Planification**

→ **Réalisation physique**

→ **Exécution financière**

→ **Indicateurs**

→ **Résultats**

→ **Écarts**

→ **Risques**

→ **Actions correctives**

→ **Évaluation**

→ **Reporting**

→ **Décision**

# 6. RÈGLE DE NON-RÉGRESSION

La refonte ne doit pas :

- casser les données PAP ;
- dupliquer le Budget ;
- dupliquer la chaîne de dépense ;
- supprimer des informations utiles ;
- casser la GED ;
- casser les workflows ;
- casser les notifications ;
- perdre les historiques ;
- écraser les snapshots de périodes antérieures ;
- casser les tableaux de bord transversaux.

Avant de supprimer un élément existant, vérifier sa fonction et ses dépendances.
