# DESCRIPTION DÉTAILLÉE DU MODULE SUIVI-ÉVALUATION  
## Application BUDGET-CEEAC

---

# 1. Présentation générale

Le module **SUIVI-ÉVALUATION** constitue le dispositif de pilotage de la performance de **BUDGET-CEEAC**.

Il permet de suivre, mesurer, analyser et évaluer la mise en œuvre des politiques, programmes, produits, sous-produits, activités et tâches inscrits au **Programme Annuel de Performance (PAP)**, tout en rapprochant les résultats physiques obtenus de l’exécution budgétaire et financière.

Il assure ainsi la continuité entre :

**Planification → Budgétisation → Exécution → Suivi → Évaluation → Reporting → Décision.**

Le module doit permettre à la Commission de la CEEAC de répondre en permanence aux questions suivantes :

- Qu’avions-nous prévu de réaliser ?
- Avec quels moyens budgétaires ?
- Qu’avons-nous effectivement réalisé ?
- Quel niveau de ressources a été engagé, liquidé, ordonnancé et payé ?
- Quels résultats ont été obtenus ?
- Quels écarts existent entre les prévisions et les réalisations ?
- Pourquoi ces écarts existent-ils ?
- Quels risques ou difficultés affectent l’exécution ?
- Quelles mesures correctives doivent être prises ?
- Quel est le niveau de performance de chaque structure, activité, produit ou programme ?

Le module SUIVI-ÉVALUATION doit donc constituer le **centre de pilotage de la performance et de la Gestion Axée sur les Résultats (GAR/RBM)** dans BUDGET-CEEAC.

---

# 2. Positionnement dans BUDGET-CEEAC

Le module SUIVI-ÉVALUATION est transversal.

Il exploite les données provenant notamment des modules :

- Budget ;
- PAP ;
- Expression de Besoin ;
- Engagement ;
- Liquidation ;
- Ordonnancement ;
- Paiement ;
- Référentiels ;
- GED ;
- Reporting.

Il ne doit pas constituer une base de données parallèle.

Il doit utiliser les données opérationnelles déjà présentes dans BUDGET-CEEAC afin d’éviter :

- les doubles saisies ;
- les divergences ;
- les incohérences ;
- les chiffres contradictoires ;
- la duplication des référentiels.

---

# 3. Principe fondamental

Le principe central est :

> **La performance doit être mesurée à partir du lien entre objectifs, résultats attendus, indicateurs, activités, ressources budgétaires et réalisations effectives.**

Le module doit permettre de rapprocher automatiquement :

- les prévisions physiques ;
- les prévisions financières ;
- les réalisations physiques ;
- l’exécution financière ;
- les indicateurs de résultats ;
- les délais ;
- les risques ;
- les observations qualitatives.

---

# 4. Référentiel GAR / RBM

Le module repose sur la structure programmatique de BUDGET-CEEAC :

**Pilier**  
↓  
**Axe stratégique**  
↓  
**Produit**  
↓  
**Sous-produit**  
↓  
**Activité**  
↓  
**Tâche**

Chaque niveau doit pouvoir être suivi et consolidé.

La hiérarchie doit être unique et partagée avec le PAP.

---

# 5. Intégration du PAP

Le PAP constitue une composante du Budget unique de l’exercice.

Le module SUIVI-ÉVALUATION ne doit donc jamais traiter le PAP comme un budget séparé.

Les éléments du PAP doivent être directement liés :

- aux lignes budgétaires ;
- aux structures responsables ;
- aux activités ;
- aux tâches ;
- aux indicateurs ;
- aux sources de financement.

Ainsi, une dépense exécutée sur une ligne PAP doit alimenter automatiquement le suivi financier de l’activité concernée.

---

# 6. Finalité du module

Le module doit permettre de :

1. planifier le suivi des résultats ;
2. suivre l’avancement des activités ;
3. enregistrer les réalisations physiques ;
4. suivre les indicateurs ;
5. mesurer les écarts ;
6. rapprocher exécution physique et financière ;
7. détecter les retards ;
8. identifier les difficultés ;
9. suivre les risques ;
10. enregistrer les mesures correctives ;
11. évaluer la performance ;
12. consolider les résultats ;
13. générer les rapports périodiques ;
14. alimenter les tableaux de bord ;
15. appuyer la décision managériale.

# 7. Dimensions du suivi

Le module doit distinguer plusieurs dimensions.

## 7.1 Suivi physique

Mesure l’avancement réel :

- tâches réalisées ;
- livrables produits ;
- bénéficiaires atteints ;
- kilomètres réalisés ;
- réunions tenues ;
- formations organisées ;
- infrastructures achevées ;
- études produites ;
- missions réalisées.

## 7.2 Suivi financier

Mesure l’utilisation des ressources :

- crédits prévus ;
- crédits engagés ;
- crédits liquidés ;
- crédits ordonnancés ;
- crédits payés ;
- solde disponible.

## 7.3 Suivi temporel

Mesure :

- délais prévus ;
- délais réels ;
- retards ;
- jalons atteints ;
- échéances critiques.

## 7.4 Suivi de performance

Mesure :

- indicateurs ;
- cibles ;
- résultats ;
- taux de réalisation ;
- évolution.

## 7.5 Suivi qualitatif

Permet d’enregistrer :

- difficultés ;
- observations ;
- risques ;
- contraintes ;
- recommandations ;
- enseignements.

- périodicité ;
- méthode de calcul ;
- source de données ;
- responsable ;
- moyen de vérification ;
- désagrégation éventuelle ;
- statut.

---

# 9. Types d’indicateurs

Le référentiel doit permettre de distinguer notamment :

- indicateurs d’intrants ;
- indicateurs d’activités ;
- indicateurs de produits ;
- indicateurs de résultats ;
- indicateurs d’effets ;
- indicateurs d’impact ;
- indicateurs financiers ;
- indicateurs de délai ;
- indicateurs de qualité.

---

# 10. Valeurs de référence et cibles

Pour chaque indicateur, le système doit pouvoir enregistrer :

- situation de référence ;
- cible annuelle ;
- cibles périodiques ;
- valeur réalisée ;
- taux d’atteinte ;
- écart.

Formule indicative :

**Taux d’atteinte = Réalisation / Cible × 100**

La formule réelle doit pouvoir être adaptée selon la nature de l’indicateur.

---

# 11. Indicateurs inversés

Certains indicateurs s’améliorent lorsque leur valeur diminue.

Exemples :

- taux d’erreur ;
- délai moyen ;
- taux d’incidents.

Le moteur de calcul doit donc distinguer :

- indicateur croissant ;
- indicateur décroissant ;
- indicateur binaire ;
- indicateur qualitatif.

---

- terminé ;
- annulé.

Un pourcentage exact peut également être renseigné.

---

# 21. Calcul automatique de l’avancement

Lorsque cela est possible, l’avancement d’une activité doit être calculé automatiquement à partir :

- des tâches ;
- des pondérations ;
- des livrables ;
- des indicateurs.

Les règles de pondération doivent être paramétrables.

---

# 22. Liaison avec l’exécution financière

Pour chaque activité PAP, le système doit automatiquement récupérer :

- budget initial ;
- budget révisé ;
- engagements ;
- liquidations ;
- ordonnancements ;
- paiements.

---

# 23. Taux d’exécution financière

Le module doit calculer plusieurs ratios.

Exemples :

**Taux d’engagement = Engagements / Budget disponible × 100**

**Taux de liquidation = Liquidations / Engagements × 100**

**Taux d’ordonnancement = Ordonnancements / Liquidations × 100**

**Taux de paiement = Paiements / Ordonnancements × 100**

---

# 24. Comparaison physique / financière

Le module doit rapprocher :

- taux d’avancement physique ;
- taux d’exécution financière.

Exemple :

Avancement physique : **40 %**

Exécution financière : **80 %**

Le système doit identifier cette situation comme potentiellement anormale.

---

# 25. Détection des écarts

Le moteur d’analyse doit pouvoir détecter automatiquement :

- faible réalisation physique ;
- consommation financière élevée ;
- retard d’activité ;
- indicateur sous-performant ;
- activité sans consommation ;
- dépense sans résultat déclaré.

---

- Vert : ≥ 90 %

Les seuils peuvent varier selon l’indicateur.

# 72. Règles de gestion essentielles

**RG-SE-001**  
Toute activité suivie doit provenir du référentiel PAP.

**RG-SE-002**  
Le PAP fait partie du Budget unique de l’exercice.

**RG-SE-003**  
Une ligne PAP doit conserver son lien avec l’activité correspondante.

**RG-SE-004**  
Les dépenses doivent alimenter automatiquement le suivi financier.

**RG-SE-005**  
Chaque indicateur doit disposer d’une unité.

**RG-SE-006**  
Chaque indicateur doit disposer d’une source de vérification.

**RG-SE-007**  
Chaque indicateur doit disposer d’une périodicité.

**RG-SE-008**  
Chaque cible doit être rattachée à une période.

**RG-SE-009**  
Les réalisations doivent être historisées.

**RG-SE-010**  
Une donnée validée ne peut être écrasée silencieusement.

**RG-SE-011**  
Les preuves doivent être conservées dans la GED.

**RG-SE-012**  
Le taux de réalisation doit être calculé automatiquement lorsque possible.

**RG-SE-013**  
Le taux d’exécution financière doit provenir de la chaîne de dépense.

**RG-SE-014**  
Les résultats consolidés doivent être calculés automatiquement.

**RG-SE-015**  
Les retards doivent générer des alertes.

**RG-SE-016**  
Les écarts significatifs doivent être justifiés.

**RG-SE-017**  
Les mesures correctives doivent avoir un responsable.

**RG-SE-018**  
Les recommandations doivent avoir une échéance.

**RG-SE-019**  
Les risques critiques doivent apparaître dans les tableaux de bord.

**RG-SE-020**  
Les rapports doivent être générés à partir des données validées.

**RG-SE-021**  
Les données financières ne doivent pas être ressaisies manuellement.

**RG-SE-022**  
Les consolidations doivent respecter la hiérarchie GAR.

**RG-SE-023**  
Les pondérations doivent être paramétrables.

**RG-SE-024**  
Les indicateurs inversés doivent être correctement interprétés.

**RG-SE-025**  
Les données doivent respecter les contrôles de qualité.

**RG-SE-026**  
Toute modification sensible doit être journalisée.

**RG-SE-027**  
Les droits doivent respecter le référentiel organisationnel.

**RG-SE-028**  
Les tableaux de bord doivent permettre le drill-down.

**RG-SE-029**  
Les données doivent être exportables selon les habilitations.

**RG-SE-030**  
Le module doit permettre le rapprochement permanent entre performance physique et exécution financière.

# 75. Résultat attendu

Le module SUIVI-ÉVALUATION doit permettre à la Commission de la CEEAC de disposer d’un système unique capable de relier :

- les ressources ;
- les activités ;
- les dépenses ;
- les livrables ;
- les résultats ;
- les indicateurs ;
- les performances.

Il doit permettre de disposer en temps réel d’une vision fiable :

- des activités exécutées ;
- des activités en retard ;
- des résultats obtenus ;
- du niveau de consommation des crédits ;
- des indicateurs atteints ;
- des risques ;
- des recommandations ;
- des mesures correctives.

Le module SUIVI-ÉVALUATION constitue ainsi la **boucle de pilotage de la Gestion Axée sur les Résultats de BUDGET-CEEAC**.

Il transforme les données budgétaires et opérationnelles de la plateforme en informations de pilotage utiles à :

- la Présidence ;
- la Vice-Présidence ;
- le Secrétariat Général ;
- les Départements ;
- les Directions ;
- les Services ;
- les organes de contrôle ;
- les responsables du Budget ;
- les responsables du PAP ;
- les responsables de Suivi-Évaluation.

Le résultat final attendu est une chaîne intégrée :

> **PLANIFIER → BUDGÉTISER → EXÉCUTER → MESURER → ANALYSER → ÉVALUER → CORRIGER → DÉCIDER**

faisant de BUDGET-CEEAC non seulement un système de gestion budgétaire, mais également un véritable **système intégré de pilotage de la performance institutionnelle**.
